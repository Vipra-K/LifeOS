# LIFE.OS setup

## Chrome
1. Open `chrome://extensions`.
2. Enable Developer mode.
3. Load the repository folder as an unpacked extension.
4. Open a new tab.

## Google Calendar OAuth
The extension uses Chrome Identity with the Calendar read-only scope. For a real connection:
1. Create/select a Google Cloud project.
2. Enable Google Calendar API.
3. Create an OAuth client appropriate for a Chrome extension.
4. Use the extension ID generated by your unpacked extension when configuring the OAuth client.
5. Replace `YOUR_GOOGLE_OAUTH_CLIENT_ID.apps.googleusercontent.com` in `manifest.json`.
6. Reload the extension.

The first connection will open Google's consent flow. Only read-only Calendar scope is requested.

## GitHub
Enter a public GitHub username in Settings. The current dashboard includes the contribution visualization shell; the next integration pass can replace the placeholder activity with GitHub profile contribution data.

## LeetCode
Enter a public LeetCode username in Settings. The dashboard is prepared for username-backed public statistics. Because LeetCode does not provide a stable first-party public API for all desired profile metrics, the data adapter should be treated as best-effort and isolated from the UI.

## Focus blocking
Focus profiles are stored locally. When a session starts, LIFE.OS creates dynamic Declarative Net Request rules: selected domains receive higher-priority allow rules and all other main-frame web navigation is redirected to `blocked.html`. Ending the session removes the rules.

The browser itself remains in control: a user who disables/removes the extension can bypass the restriction. This is a productivity guard, not an administrator-level lock.
